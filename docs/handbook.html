crapkit

A deterministic change-risk gate for TypeScript, TSX, JavaScript, Python, Swift, Go, Rust, shell, PowerShell, C and C++, Objective-C, Vue, Java and Zig. It scores every function on complexity times uncovered risk, ranks the worst by how often their files change, hands a coding agent everything it needs to fix one, and blocks commits that add more.

CRAP = ccn2 × (1 − cov)3 + ccn

Yes, the name is real and it is not ours: C.R.A.P. — Change Risk Anti-Patterns — was coined for crap4j by Alberto Savoia and Bob Evans in 2007. An honest score deserved an honest name. We just built the kit.

01Why crapkit exists

Two facts about production defects meet in one number.

Complex functions break more, and untested functions break silently. The CRAP metric multiplies the two: cyclomatic complexity squared, times the cube of what your tests never touch. A simple covered function scores near its complexity. A complex uncovered one explodes — the largest one crapkit has scored in the field was an anonymous handler at ccn 220 with no tests, CRAP 48,620.

Plenty of tools report complexity, and plenty report coverage. crapkit's reason to exist is what it does after the arithmetic:

  • It ranks by consequence. Debt in a file that changes weekly outranks identical debt in a file nobody has touched in a year — the risk map is ordered by ccn × churn weight, not by score alone, and the hand-out queue takes the worst CRAP first.
  • It gates the future, never the past. A brownfield repo turns the gate on the same day it installs: standing debt is recorded in a committed ratchet and pardoned; only touched functions are judged. A repo-wide day-one gate fails forever and gets disabled — crapkit refuses to be that tool.
  • It briefs the fixer. One command emits a start-editing packet: the function's own source, every sibling in its file, the ceiling it will be judged by, the lane that measures it, the exact commands to run, and the repo's written-down traps. A session starts editing instead of exploring.
  • It is deterministic. Same tree, same config, same answer, byte for byte. Every read command emits JSON with a pinned schema (under --json; next-item always; digest alone stays plain lines by design), because half the callers are coding agents.

02The score

ccn is cyclomatic complexity — the count of independent paths through a function — taken as the smaller of lizard's standard and modified counts (modified treats a whole switch/match as one decision). Comprehension for/if, ternaries, and and/or all count. cov is branch coverage inside the function's span; with no branches it falls back to statement coverage, and with no statements to invoked-or-not, so a half-executed straight-line function never reads as fully covered.

The ceiling theorem

Because full coverage still leaves CRAP = ccn, a target is secretly two rules in one. At the default target of 6 — a crapkit.toml knob, set per repo or per scope, and the number every packet and every gate message calls the ceiling — a function at ccn 7 with 100% coverage scores 7 and fails. Above the ceiling, coverage cannot save you — the only clearing move is decomposition. Below it, the target prescribes exactly how much coverage each complexity owes:

A Sonar-spec cognitive complexity column rides along in the brief and next-item payloads as a second opinion on readability, measured in every language crapkit scans. It reports; it never gates — the gate is min-ccn only, so the rule a commit is judged by has one definition.

03How it works

One pass of analysis, your own test commands for coverage, one SQLite store, many views.

  • Scopes carve the repo into named territories (src, ui, py…), each with its languages, an optional per-scope target, and free-text notes — the written-down operational traps that ride into every packet.
  • The inventory is one lizard tokenization per file, content-hash cached, producing both ccn variants and cognitive complexity for every function.
  • Lanes are your repo's own coverage commands with a watchdog, retries, and provenance stamps. A failed lane marks its scopes no-lane and the run partial — visible, never fatal, never a baseline.
  • The store keeps scored runs compactly (function identity written once, referenced per run), plus claims, overrides, and run history. runs prune is the retention knob.
  • Churn comes from the git log over a configurable window, cached deflated and refreshed incrementally, so the expensive walk happens rarely.
  • Languages are the table below. Two of them run on readers crapkit wrote and one on a reader crapkit corrected, because lizard's answer was wrong rather than missing.

What crapkit reads

The left column is the label a crapkit.toml spells in languages = [...]. A file joins a scope only when its path prefix and its extension both match. Coverage is how a percentage arrives: crapkit ships two artifact parsers and no more, so most of this table scores cc-only — crap = ccn, under coverage_optional = true, with no lane to run.

What each row costs you to know:

  • Rust runs on a corrected reader: lizard lists match as a keyword and counts no arm (lizard #494), so a seven-arm dispatch scored 2 while the if/else-if chain doing the same work scored 4. crapkit counts one point per non-wildcard arm and retires the reader the day upstream fixes the issue — a test pins the stock reader's wrong answer, and it fails on that release.
  • shell gets a reader lizard ships none of, and reports functions only: top-level script code belongs to lizard's *global* pseudo-function, exactly like Python module level. A script that is one long top-level sequence reports nothing, and that is the answer rather than a parse failure.
  • PowerShell gets a reader too, and it counts one point per switch arm rather than one for the block — a twelve-arm dispatcher should not score the same 2 as a one-arm one. Source bytes are decoded utf-8 first and cp1252 second, by content instead of by the machine's locale: Windows PowerShell writes cp1252 by default, and left to io.open the same file scored one way on Windows and another on Linux.
  • C and C++ are one label, cpp, C included: lizard resolves all six suffixes to one reader, so two labels could never measure differently, and .h is the header both dialects share. A && before the opening brace declares an rvalue reference rather than deciding anything and costs no cognitive complexity — the same rule covers objectivec, since .mm is Objective-C++. Both arms of an #ifdef fork are textually present, so a platform shim defines one function twice in one file; a ratchet mark keys on (path, long_name) and keeps the last, and analyze prints one stderr line naming any file that happens in.
  • Vue scores the <script> block. Template directives (v-if, v-for) are HTML attributes to lizard and contribute nothing, so a component that branches in its template reports only what its methods do. Zig counts a switch's else prong as one more case, so a Zig switch reads one point above its hand count — inflation only, which can cost a refactor that was not needed but never hides one that was.
  • Kotlin is measured correctly and still not admitted. lizard's KotlinReader records only brace-bodied functions, so fun sign(x: Int) = if (x > 0) 1 else if (x < 0) -1 else 0 yields no function at all and its two decisions land nowhere, not even in *global*. A language that can hide arbitrary branching from the gate is worse than one crapkit refuses, so the label waits on upstream.

Most of what you just read is a dial

Almost every behavior above is a crapkit.toml key with a deliberate default, not a constant. The ones people reach for first:

[crapkit]
target = 6                  # THE dial: the CRAP ceiling, and with it the ccn ceiling
churn_window_months = 12    # how far back "hot" looks
worklist_floor = 5          # admission floor for the risk map (never hides over-ceiling debt)
diff_uncovered_max = 40     # optional: verify exit 9 when a change leaves more dark lines
max_parallel_lanes = 3      # how many coverage lanes run at once
notes = ["…"]               # repo traps, delivered inside every packet

[[scope]]
name = "legacy"
target = 10                 # a scope can carry its own ceiling…
coverage_optional = true    # …or opt out of coverage entirely (crap = ccn, cc-only)

[[lane]]
timeout_seconds = 2400      # per-lane watchdog
retries = 1                 # and how often a flaky lane gets another shot

Per-scope targets are how a repo holds new code to 6 while a quarantined legacy tree ratchets down from 10. Every key, with type, default, and what it does, is in docs/configuration.md — and doctor tells you when the file and the repo have drifted apart.

04The queue: two views of one run

One scored run, two deliberately different lenses — a map for judgment, a queue for hands.

Reading a worklist row

risk      5.4  ccn   6 (  6 std)    5c/1a w   0.90  src/crapkit/cli/reports.py:62  cmd_digest( args )

  risk 5.4 .......... ccn x churn weight - what ranks this map
  ccn 6 (6 std) ..... min(standard, modified) ccn, standard in parentheses
  5c/1a w 0.90 ...... 5 commits, 1 author in the window, recency weight 0.90
  path:62 ........... file and the line the function opens on
  cmd_digest( args )  the long name - paste it straight into `crapkit brief`

Risk is ccn × churn weight, where the weight favors recent activity: five commits last month outrank one commit each of five months. A function over its ceiling is admitted whatever its ccn — the admission floor (worklist_floor, default ccn 5) trims the list, it never hides debt. Hot-but-simple code appears too (that is the map doing its job); the ok marker says no action is owed.

The termination rule: knowing when a burn-down is done

Three conditions, all at once, from next-item: empty: true, no items skipped because another session claims them, and no no_lane_over_target count in the reasons — debt a wiring gap keeps unreachable is still debt. One flag alone is not done.

05The packet

The first half hour of any refactor is reading. brief deletes it.

Ask about one function and the reply is a start-editing packet: everything a session would otherwise assemble with an editor, a grep, and three git commands. The fields group into five questions:

  • Batch mode: brief --batch N --json emits the top N queue items as N packets from one process — one store open, one churn load, one source read per file. An orchestrator dealing work to parallel agents pays the fixed costs once.
  • Four name forms: the long name the worklist prints, the bare name, the start line, or the ordinal handle (anonymous)#N — the Nth anonymous function in the file by start order, a name that survives edits shifting lines above it. claims accepts the same forms.
  • Honesty flags: stale says the snapshot predates HEAD; uncovered_lines: null plus a note names the lane that abstained (never conflated with "nothing to cover"); refresh_writes_run warns that refreshing writes a run.

06The gate and its four routes

One rule — every touched function at or under its scope's ceiling — enforced at four distances from the keyboard.

Exit codes are the API

ExitMeaningThe move
0Verdict cleanProceed. (For verify, this is the green that ends a loop iteration.)
1Overloaded: no data yet, a doctor FAIL, or a debt-policy breachRead the message; it names the command that creates the missing run, or the FAIL line. README's exit table splits the three.
2Usage errorargparse refused; check the flag spelling and order.
3Config gapA scope without a template, a metric-stamp mismatch — fix crapkit.toml or restamp.

9Changed lines nobody coveredOnly in repos that set diff_uncovered_max.

verify reports the first of 6, 7, 8, 9 that fires, in that order — a CI script branches on one code per run.

07The ratchet

How a brownfield repo turns the gate on today instead of “after the cleanup”.

crapkit ratchet seed writes every standing over-target score into crapkit-ratchet.tsv — a committed, human-readable file of pardons. A mark pardons debt at or under its recorded score: the function may stay bad, but it may not get worse, and when someone improves it the mark tightens automatically at the next green verify. Debt can only shrink. That is the ratchet.

Marks carry a metric-version stamp: if a future crapkit changes how ccn is counted, verify refuses to compare marks across metrics instead of silently re-judging old pardons with new math. Optional policy knobs add expiring debt and repayment quotas for teams that want the screw to turn on a schedule.

08The trusted baseline

Every verdict compares against one earlier run. Which one is a rule, not a guess.

Qualifying runs are coverage runs and passing verifies. A failed verify never qualifies — and more: it taints what follows. Runs taken after a failure are skipped by default baseline selection until some verify passes, so nobody retires findings by quietly re-running coverage on the refused tree.

runs list marks the row verify compares against today, and warns when a moved HEAD makes the snapshot stale. For repos with no store at all — a CI clone — verify --emit-baseline on the main branch writes a commit-stamped TSV that verify --baseline-tsv reads in the PR, with --github annotations on the diff.

09Lanes: how coverage arrives

crapkit runs no test framework of its own. A lane is your command, its artifact, and a parser.

[[lane]]
name     = "unit"
command  = "npx vitest run --coverage --coverage.reportsDirectory=.crapkit/cov/unit"
artifact = ".crapkit/cov/unit/coverage-final.json"
parser   = "istanbul"          # or "coveragepy"
scopes   = ["src"]
  • Provenance: every artifact is stamped with the commit and duration that produced it; stale artifacts are named, never silently reused. --reuse-unchanged reruns only lanes whose scope files moved.
  • Resilience: per-lane timeout_seconds and retries; a configured retest_command reruns just the newly-failing tests before exit 8 calls them real. Lanes run in parallel up to max_parallel_lanes, longest first.
  • Honest failure: a lane that produces no artifact marks its scopes no-lane and the run partial — the queue counts what it cannot see instead of pretending. The four classic causes (a coverage provider not installed, a red suite with report-on-failure unset, a report landing where the lane does not look, a watchdog kill) are triaged in docs/lanes.md.
  • The test template: a [crapkit.scoped_tests] entry per scope says how to run that scope's tests in isolation — it is what crapkit test-scoped executes, what the packet's commands.scoped_tests carries, and what doctor warns about when a laned scope has none.
  • Housekeeping: everything writes under .crapkit/; doctor warns about lanes littering the repo root, dead commands, unclaimed files, and scopes with no test template.

10Built for agents

Half of crapkit's callers are language models. The tool treats that as a design constraint, not an afterthought.

Claims

Parallel sessions coordinate through next-item --claim: a claimed item is skipped by everyone else, released on green verify or by hand. Handles survive line shifts.

Batches

worklist --batches N cuts the queue into file-disjoint batches (co-changing files kept together) — a fleet plan with no overlap by construction.

MCP server

crapkit mcp: a dependency-free stdio server exposing the read side as tools. Register globally; in an unmeasured directory it answers with guidance instead of dying.

Skills

skills/ in this repo ships agent skills (the loop, the failure router, a decomposition catalogue). A contract test pins their text to the CLI so they cannot drift.

Notes

Repo and scope notes in crapkit.toml ride into every packet — the channel for hard-won operational traps, delivered at the moment of use.

Pinned JSON

Every read command emits JSON under --json (next-item always; digest alone is plain lines by design); payloads carry schema: 1 and change additively only. crapkit report is the one human form: it renders those same payloads into one static HTML page.

11Install and first run

pip install git+https://github.com/JeanFrancoisGagne/crapkit.git   # or: pip install . from a clone

Python 3.11+. One runtime dependency (lizard). Then, in the repo you want scored:

StepCommandWhat happens
1crapkit initSniffs tracked source into scopes; detects pytest/vitest/jest from the repo's own files and writes live lanes; scaffolds .gitignore and a test template for runners it could prove.
2crapkit doctorChecks the config against reality: unknown keys, unclaimed files, dead lane commands. Exits 1 only on FAIL.
3crapkit coverageRuns the lanes, joins coverage onto a fresh inventory, writes the first scored run and its grade.
4crapkit ratchet seedPardons standing debt into crapkit-ratchet.tsv; commit it.
5crapkit worklistRead the risk map: what is worst, and how hot it runs.
6printf '#!/bin/sh exec python -m crapkit hook-precommit ' > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commitArm the gate. From here every commit is judged — new debt only; the seeded marks pardon the old. The README's gate section has the committed-hooks-dir, pre-commit-framework, and CI routes.

The full walked-through quickstarts (Python and TypeScript, with real transcripts) live in the README; the judgment calls — scope granularity, exclude versus lane, the first-verify hazard — in docs/adoption.md.

13The analysis cabinet

mutate — are the tests real?

Diff-scoped mutation testing: flips comparisons and boolean logic on the lines you changed, runs the suite per mutant, lists survivors. The audit for coverage that moved the number without testing anything.

duplication — does this already exist?

Near-duplicate function detection by shingle similarity, containment-aware so an enclosing function is not reported as its own twin.

coupling — what changes together?

Files that co-change across the churn window, with support and confidence. The blast-radius map for a refactor.

trend — is it getting better?

Totals per scored run: over-target count, CRAP load, grade. The burn-down chart's data.

doctor — does the config still fit?

Every drift between crapkit.toml and reality, as WARN or FAIL. Run it after any rename.

overrides — who granted what?

The audit trail behind every gate override: who, when, why, and the debt it staged.

14The campaign: fixing a whole codebase

Everything above composes into one flow when the goal is the whole repo. Four phases — and the gate goes on first, not after the cleanup.

  • Doctor's warnings are the first work items. Debt in a scope no lane measures cannot be burned down, only wired up — on one large consumer, wiring six extra lanes took measured functions from 95k to 113k of 141k before a single function was edited.
  • The stop signal is the termination rule (§04), never an empty-looking worklist. A finished repo is a worklist full of ok markers.
  • Value is front-loaded, so stopping early is rational. The risk map is worst-first by ccn × churn and the hand-out queue by CRAP; the top of it is where incidents live. “Fix the worst slice and gate the rest forever” is the same campaign ended earlier — and the ratchet holds whatever line you reach. (The shared ratchet file is the one file every branch touches; that is what the ratchet merge driver exists for.)
  • The summit items are redesigns. A whole command handler at extreme ccn is not a split, it is an architecture session; the packet's est_splits saying dozens is the tell.
  • Proof it composes: crapkit's own repo ran this exact campaign against its own gate — every standing mark repaid, the ratchet file now header-only, grade A+.

15Design principles

  • Deterministic or wrong. Same tree, same config, same bytes out. Randomness, wall-clock dependence, and unstable orderings are treated as defects.
  • The gate binds the future. Standing debt is pardoned and ratcheted; only touched functions are judged. A gate a team turns off is worse than no gate.
  • Above the ceiling, decompose. Coverage cannot save a function past its target — the design pressure is the point, and crapkit's own source is held to its own rule.
  • Additive JSON, pinned schema. Fields are added, never renamed or removed; schema: 1 means an agent's parser written today keeps working.
  • Your test commands, not ours. Lanes run what the repo already runs; crapkit reads artifacts. There is no embedded test framework to fight.
  • Failure is data. A failed lane, a stale artifact, an abstaining scope — each is counted and named, never papered over with a zero that reads as health.
  • Docs are contracts. Tests diff the README's command table against the argument parser, and the shipped skills against the CLI, both directions. Documentation that can drift, will — so it is not allowed to.
  • Dependency-light. Python stdlib plus lizard. The MCP server, the parsers, the store — no framework underneath to version-chase.
