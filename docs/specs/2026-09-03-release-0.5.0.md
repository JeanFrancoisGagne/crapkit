# crapkit 0.5.0: the seventeen repairs from the seven-seat review

Status: grill converged 2026-09-03 (three rounds, nineteen decisions below); published as issue #58 (https://github.com/JeanFrancoisGagne/crapkit/issues/58) with the ready-for-agent label. Source: the 2026-09-03 UX review
of 0.4.15, in which seven personas used crapkit for real, three designers proposed
changes, a judge ranked fourteen behind an identity gate, and a skeptic per item checked
each against the code. Everything below is scoped to what those seats hit.

## Problem Statement

crapkit computes one number per function and ranks the worst; 0.4.15 is correct about
that number and quiet or wrong about the things around it. A coding agent that calls an
MCP tool with one argument missing kills the server and every later call reads end of
file. A first-time user runs `worklist`, the ranking view of a CRAP scorer, and never sees
a CRAP score or a coverage figure on it; the HTML report tells them to leave the page and
run `explain` per row. A maintainer who asks `verify --override` to accept a hotfix is
refused in silence, exit 6, no line, no audit row. A platform engineer who adopts the
Action with `actions/checkout` defaults (depth 1) gets a green check on a pull request
that fails the gate at full depth, with a comment that says "verify passed". A monorepo
lead's first `next-item` is a generated client at crap 90 because the default excludes
only match generated trees at the repository root. A typo in `--scope` returns an empty
ranking with exit 0, which CI reads as clean. A stale coverage artifact survives a failed
lane and becomes the trusted baseline. `init` writes a scoped-test command that collects
zero tests on the most common Python layout. Every command exits 3 from a subdirectory of
a configured repository. The PR comment shows counts and a table where signed debt and
the PR's own new function look identical. `digest` and `trend` disagree on the same run
pair because five call sites spell the per-scope ceiling five ways. On Windows the hook
and the MCP server read stdin in the locale code page, so a non-ASCII path yields
silence. A one-commit repository ranks every row at risk 0.0. And after an edit, nothing
an agent can call answers "does my change clear the ceiling".

## Solution

0.5.0 repairs the seventeen findings without adding a linter, a dashboard, a test runner
or a coverage tool: crapkit still reads the coverage artifact the suite already writes,
still inventories with lizard, still ranks by churn, still keeps its committed ratchet
and gates new code. What changes is that the number the tool exists to compute is on the
ranking view and the report; refusals and judgements speak; the MCP server survives bad
input and grows one read-only tool that answers the post-edit question; the Action never
calls a pass on a run that judged nothing; excludes, scopes and configuration discovery
behave the way a monorepo user expects; summaries agree with each other; and Windows
reads and writes UTF-8.

## User Stories

1. As a coding agent, I want a `tools/call` with a missing or unknown argument to come back as a tool error in the tool's own words, so that my session survives my mistake and I can correct it.
2. As a coding agent, I want `ping` answered, so that my client's keepalive does not read as a protocol error.
3. As a coding agent, I want `explain` and `doctor` to return structured JSON like the other tools, so that I parse one shape.
4. As a coding agent, I want `explain` to accept `history` and `tests`, so that the flags the CLI already has reach me.
5. As a coding agent, I want the `tools/list` schema to declare which arguments are required, so that I can plan a call before making it.
6. As a first-time user, I want every `worklist` row to show the function's CRAP score and coverage, so that the ranking view answers the question the tool exists for.
7. As a first-time user, I want the `worklist` header to say how many active rows the cap hid, so that "50 active" on a 4,000-function repo does not read as 50 in total.
8. As a report reader, I want CRAP and coverage columns on the HTML report's worklist table, so that I do not have to run `explain` per row.
9. As a maintainer, I want `verify --override` to say why it refused when it refuses, so that a hotfix with a ratchet regression is not a silent exit 6.
10. As a maintainer, I want the OK line of `verify` to say what it changed in the marks file and to remind me to stage it, so that a dirty ratchet file after a green run is not a surprise.
11. As a maintainer, I want `verify` to leave the marks file untouched when nothing changed, and never to create one that holds zero marks, so that a clean checkout stays clean.
12. As a platform engineer, I want the Action to say plainly when the base run could not be made and why (shallow clone, no config at the fork point, lane failure), so that I fix the workflow instead of trusting a verdict that judged no changed function.
13. As a platform engineer, I want `gate: true` to fail the job when the base run was attempted and failed on a pull request, so that a depth-1 checkout cannot produce a false pass.
14. As a platform engineer, I want the "not an ancestor" error to distinguish a shallow clone from a rewritten history, so that the hint I follow is the right one.
15. As a monorepo lead, I want `**/` in an exclude glob to match zero or more directories, so that one glob covers the root and every nested copy.
16. As a monorepo lead, I want generated trees excluded by default, so that a generated client is not my first `next-item`.
17. As a config author, I want the default excludes written once each, one per line, so that I can read and edit them.
18. As a CI author, I want an unknown `--scope` to exit 3 and name the declared scopes, so that a typo cannot read as a clean pass.
19. As a coding agent, I want the `worklist` and `next_item` MCP tools to accept a scope, so that I can partition a large repository before I ask for the top rows.
20. As an operator, I want `--reuse-artifacts` to refuse an artifact that the last lane attempt failed to write, so that a dead lane's old numbers never become the trusted baseline.
21. As a platform engineer, I want the Action to skip `verify` when `coverage` failed and to say so in the comment, so that the verdict line never reports a pass over a failed measurement.
22. As a Python user with `src/` and `tests/` side by side, I want `init` to write a scoped-test command that collects tests, so that the loop's test step works on its first run.
23. As a monorepo lead, I want `init` to write the workspace's own test command for a workspace scope, so that the right runner runs in the right directory.
24. As a user, I want `doctor` to repeat `init`'s lane probe and name the resolved interpreter and plugin versions, so that a lane that cannot import pytest-cov fails `doctor` instead of the first `coverage`.
25. As a user in a subdirectory of a configured repository, I want every command to find the configuration the way git finds `.git`, so that `cd web && crapkit worklist` works.
26. As a user in a subdirectory, I want relative path arguments rebased from where I stand, so that `crapkit brief src/grade.ts classify` from `web/` names `web/src/grade.ts`.
27. As a monorepo lead, I want `init` to refuse to write a second configuration under an ancestor that already claims the directory, so that two configs never claim the same files.
28. As a reviewer, I want the PR comment to name the function and the rule that failed, so that I do not read the job log to learn which line the gate stopped.
29. As a reviewer, I want signed debt marked in the comment's table, so that an untouched ratchet-marked function does not look like the PR's own new function.
30. As a reviewer, I want the diff-coverage ceiling and the uncovered changed lines in the comment when exit 9 fires, so that the reason is where the verdict is.
31. As a maintainer with several scopes, I want `digest` and `trend` to count the same functions over the same per-scope ceilings, so that they agree on the same run pair.
32. As a user, I want the coverage summary to say when a run is partial, which scopes went unmeasured, which ceilings applied, and what to run next, so that a `--lane` run is never mistaken for a baseline.
33. As a CI author, I want `--json` to print one error object on stdout when a command dies, so that the comment renderer shows the sentence that names the fix instead of "wrote no run summary".
34. As a Windows user, I want the hook and the MCP server to read stdin as UTF-8, so that a non-ASCII path produces the advisory instead of silence.
35. As a Windows user, I want a configuration or marks file saved with a BOM to read as the same file, and a UTF-16 one to fail with a sentence that names the fix, so that PowerShell's `Out-File` default is not a traceback.
36. As a Windows user, I want the one-liners that shells capture to be ASCII, so that a captured header does not hold mojibake.
37. As a Windows user, I want `doctor` to warn on a hook file git cannot spawn (BOM or UTF-16), so that the failure is found before the first commit.
38. As a user of a one-commit repository, I want rows ranked by complexity instead of every row at risk 0.0, so that the first worklist means something.
39. As a coding agent, I want a read-only MCP tool that judges my edited file against the ceiling and returns the breaches, so that I know whether my change clears the gate before I commit.
40. As a CLI user, I want `rescore --gate --json` to carry the verdict in its payload and the text form to say when the gate passed, so that the exit code is not the only signal.
41. As any user, I want every default, message and exit code above documented where the old behavior was documented, so that the docs and the tool agree.
42. As a user upgrading from 0.4.x, I want a CHANGELOG section that names each behavior change and the command to run after upgrading, so that a moved corpus or a new exit code is not a surprise.

## Implementation Decisions

Numbering follows the review's ranking. Every item stays inside the 0.4.x house rules
except the version: TDD, every function at ccn 6 or under, no new dependency, contract
tests moved deliberately and named in the commit.

1. **MCP server survives bad input.** Arguments are validated against the tool table before the CLI is spawned: a missing positional, an undeclared key or a wrong type answer `isError` in the tool's vocabulary (this follows the house precedent for unknown tool and missing config, not the protocol's `-32602` example, and the docstring says so). `tools/list` emits `required`. `ping` answers an empty result. The serve loop turns an escaped exception into a JSON-RPC `-32603` reply and continues. `explain` and `doctor` run with `--json`; `explain` gains `history` and `tests`. Structured content is attached when the tool exits 0; a failing `doctor` returns JSON text without it, and the docs say so. Docs: the MCP table in the agent JSON page and the agents guide lose the "plain text" rows; the stale protocol revision line in the agents guide is fixed.
2. **Worklist rows carry the number.** Rows gain `crap` and `cov` (null on an inventory-only run) read in the same query as flag and remedy. The text row shows `crap` and `cov` and drops `(N std)` and `w 0.00`; JSON keeps `ccn_std` and `weight`. The header reads `50 of 3980 active (worklist_top 50), 0 dormant` and JSON gains `active_total`, distinct from the over-ceiling total that `trend` and the coverage summary already carry. The HTML report renders CRAP and Cov columns; the footer sentence and the README sentence claiming no repo-wide payload carries them are deleted, since `next-item --json`, `coverage --export` and `brief --batch` already do. The "hot" and "over-target" markers on rows admitted under the floor are deferred (no reason plumbing exists; separate slice). The demo recording is re-rendered.
3. **verify says what it did.** A refused override prints one stderr line naming the cause (ratchet regression or new test failure) and the escape (raise the mark by hand and commit it); the ratchet page states the rule. The marks file is written only when its text would change and never created to hold zero marks. The OK line gains `ratchet: N dropped, M tightened -> git add <marks file>` when it wrote; the JSON receipt gains `ratchet_changes`. A pure ratchet-delta function returns the counts.
4. **The Action never calls a pass on a judgement of nothing.** The base step records a reason on every failure path (shallow clone, no config at the fork point, lane failure, or "no base commit" on push and `delta: false`). The comment renders `verify judged no changed function: the base run was not made (<reason>)` in place of `verify passed` when there is no base. With `gate: true`, the exit step exits 1 only when the base step was attempted on a pull request and failed; push and `delta: false` keep verify's exit and the honest line. The ancestor check says "shallow clone" when `git rev-parse --is-shallow-repository` is true and keeps the rewrite message otherwise, exit 4 unchanged. The comment renderer stays git-free.
5. **`**/` matches zero or more directories.** The exclude matcher compiles a leading `**/` as an optional directory prefix. The default excludes drop the root duplicates and add `**/generated/**`, `**/__generated__/**`, `**/*.generated.*`; `init` writes one glob per line under a two-line comment. Hand-written root forms keep matching. This moves corpora for committed configs (a root `dist/` leaves under `**/dist/**`); the configuration page gets the same "run doctor after upgrading" note it already carries for the last corpus-moving upgrade, and the CHANGELOG reverses 0.4.12's duplication rationale by name.
6. **Unknown scope is a configuration error.** A scope-name validator returns the declared list or raises the loader's configuration error, exit 3, naming the declared scopes; `worklist` and `next-item` call it before touching the store (`brief` has no scope flag and is not touched). The `worklist` and `next_item` MCP tools declare `scope` as an array of strings. The two e2e tests that used an undeclared scope as their vehicle move to a declared, empty scope.
7. **A failed lane's old artifact is refused.** The refusal that `coverage` already computes (which artifacts the lane did not write, and their mtimes) is persisted through the existing stamps path; on reuse, an artifact whose mtime equals the refused one is refused with the same tool error (exit 5 for `coverage`, "cannot conclude with failed lanes" for `verify`). A salvage written after the failure has a new mtime and reuses, so the shard recipe holds. The lane-log-mtime predicate is rejected (the log's exit line is written after the artifact). The Action's verdict step reads coverage's exit first and does not call `verify` when it is non-zero; the comment says `no verdict: coverage exited 5 (<first line of the lane failure>)`, with a fallback when every lane failed and no summary was printed. Two written promises about `--reuse-artifacts` being untouched are rewritten.
8. **init writes a scoped-test command that collects a test.** A Python scope whose paths hold no test file gets the whole-suite form; `{files}` stays only where tests live under the scope's own paths. An npm workspace scope with a test script gets `npm run test -w <dir>`; a root JavaScript scope gets the runner's related-tests mode keyed by runner (vitest, jest). One comment line names the form chosen. `doctor` re-runs `init`'s first-run lane note per coverage.py lane, prints the resolved interpreter and plugin versions on ok, warns when the interpreter is not the current one, and fails a `{files}` template whose scope holds no test file. Init's summary also says when two workspaces name a runner and no js lane was written.
9. **Configuration is found upward.** The hook's root walk becomes a shared stdlib-only module; every command uses it when `--repo` is not given (`--repo` now defaults to none; a given `--repo` names an exact root). When the found root differs from the working directory, one stderr line says which configuration is in use, and relative path arguments are rebased from the working directory. A `.git` entry without a configuration stops the walk, so a linked worktree never borrows a parent's store; nearest configuration wins. `init` refuses, exit 3, when an ancestor configuration already claims the directory through a scope path, and skips the nested `.gitignore` append when an ancestor already ignores the state directory. The MCP server and `init` walk the same way. The lanes page's "no monorepo mode" sentence is replaced.
10. **The PR comment names the finding.** `verify --json` adds `diff_uncovered_max`. The renderer maps the exit code to a fixed phrase and prints one bullet per gate violation, ratchet regression, new failure, and the first twenty uncovered changed lines grouped per file, above the counts line it keeps verbatim. Worklist rows gain `ratchet_mark` (the committed mark's value or null), keyed the way `brief` keys marks so twins never take each other's mark; the comment appends `(accepted debt)` to marked rows and lists rows named by a finding first. The README's rendered comment is regenerated from a failing example.
11. **One ceiling predicate, one run-shape label.** A single per-scope ceiling accessor replaces the five spellings, and `digest` takes the per-scope ceilings so `digest` and `trend` agree. The coverage summary carries kind (coverage or partial), unmeasured scopes, the ceilings in force and lane failures on every path; the text opens with `partial run (...)`, counts over-ceiling and grade over measured scopes only, drops zero buckets, labels the ceiling or ceilings, and ends with the next command. When a crapkit error escapes under `--json`, stdout still prints one object `{"error": {"exit", "kind", "message"}, "schema": 1}` and the exit code is unchanged; the comment's scored line quotes the ceilings and the first line of a lane failure or the error message.
12. **UTF-8 in, tolerant reads, ASCII one-liners.** A non-tty stdin is reconfigured to UTF-8 with replacement, covering the hook and the MCP server. One repository-text reader decodes with `utf-8-sig` and turns a decode error into a configuration error naming UTF-16 and the fix; configuration, marks and stamp reads go through it (the hook inlines its copy to keep its import rule). The six one-liners shells capture use an ASCII separator. `doctor` warns on a hook file whose first bytes are a BOM or UTF-16. The README's hook route gains the PowerShell form.
13. **A one-commit repository ranks by complexity.** The time-weighted-recency function returns 1.0 when the newest and oldest commit times coincide, and the hot promotion is off when every weight is equal. Repositories with two or more commit times are unchanged.
14. **A tenth MCP tool answers the post-edit question.** `rescore --gate --json` adds a `gate` object (judged count, ceilings per path, breaches with path, function, start, ccn, cov, crap, remedy, key name, ceiling, untracked files, ok), exit 6 on a breach unchanged; the text form prints the gate line when it passes. A tool named `gate` maps to `rescore PATH --gate --json` with the same read-only annotations; the MCP runner treats exit 6 from this tool as a result with `ok: false` and structured content, while exits 3, 4 and 5 stay tool errors.

15. **Python nesting is a depth, not a count.** For Python rows `nesting` is derived from crapkit's own cognitive pass, which tracks a per-function nesting stack, instead of lizard's nesting-structure count; brace languages keep lizard's depth. A flat seven-`if` function reads depth 1, a three-deep one reads 3. The agent JSON page names the source of the field. (Design pass pending in the grill.)
16. **The lane guard knows pytest's `testpaths`.** A positional argument that equals a configured `testpaths` entry (pyproject, pytest.ini or setup.cfg) no longer counts as narrowing the run, so `pytest tests` with `testpaths = ["tests"]` passes doctor, coverage, digest and ratchet seed. `init` omits the positional when the configured `testpaths` already covers it. (Design pass pending in the grill.)
17. **`mutate` never mutates a test.** The diff's file list passes through the same corpus predicate as scoring (scopes, excludes, the test-file cut) before mutants are placed, so a diff that touches `tests/` produces mutants only in the source files it also touches. (Design pass pending in the grill.)

Cross-cutting: the release bumps every version surface including the registry manifest; the CHANGELOG carries an "Upgrading from 0.4.x" section listing items 2, 5, 6, 9, 11 and 16 as behavior changes and `crapkit doctor` as the command to run after upgrading; the registry entry is republished after PyPI.

## Decisions from the grill (2026-09-03)

1. Version 0.5.0 opens the line; 0.5.1 is the first repair.
2. Four existing seams: the CLI process, the MCP stdio client plus one in-process serve-loop test, the Action's comment renderer and contract tests, the docs contracts moved in the same commit as each behavior.
3. The three set-asides (items 15 to 17) ship in this release.
4. Behavior changes ship as new defaults with an "Upgrading from 0.4.x" section and `crapkit doctor` as the post-upgrade command; no compatibility flags.
5. Invalid MCP arguments answer as a tool result with `isError` in the tool's words, following the house precedent for unknown tools and missing configuration, not the protocol's `-32602` example.
6. The worklist text row drops `(N std)` and `w 0.00`; JSON keeps `ccn_std` and `weight`; the handbook legend and the demo recording change.
7. With `gate: true` the Action exits 1 for a missing base only when a pull-request base run was attempted and failed; push and `delta: false` keep verify's exit and render the honest line.
8. Discovery walks up from the working directory; the nearest configuration wins; a `.git` entry without a configuration stops the walk; one stderr line names a root that is not the working directory; relative path arguments are rebased.
9. The tenth MCP tool is named `gate`.
10. Glossary: ceiling is the concept in prose, messages and the new accessor; `target` stays the configuration key (recorded in CONTEXT.md).
11. Reuse refusal persists the refused artifact mtimes through the existing stamps path; the lane-log-mtime rule is rejected.
12. The override refusal is one stderr line covering both causes; `--json` stdout stays one object.
13. Python nesting is derived from the cognitive pass; brace languages keep lizard's depth.
14. The lane guard accepts a positional equal to a configured pytest `testpaths` entry; `init` omits a redundant positional.
15. The MCP scope argument is an array of strings, one `--scope` each.
16. Two ADRs record the surprising choices: invalid MCP arguments as tool results (ADR 0001) and upward configuration discovery with nearest-wins and the `.git` stop (ADR 0002).
17. Under `--json`, an escaped crapkit error still prints one object on stdout, `{"error": {"exit", "kind", "message"}, "schema": 1}` with `kind` in config, git, tool; the exit code and the stderr line are unchanged.
18. Worklist rows carry `ratchet_mark`, the committed mark's value or null, keyed through the twin-aware key; the comment appends `(accepted debt)` when it is not null.
19. Delivery: seventeen vertical slices built in parallel worktrees by Fable 5.1 builders, reviewed and fixed by Fable 5.1, merged serially, then the 0.5.0 release chain and a registry republish.
20. The six shell-captured one-liners use an ASCII separator (a consequence of decisions 4 and item 12); the docs contracts that pin the em dash move with them.

## Testing Decisions

A good test here drives a public seam and asserts observable behavior: the exit code, the text or JSON a user or agent reads, the file a command wrote or refused to write. No test reaches for a private function's return value when a command's output shows the same fact.

Seams, from the top down, preferring existing ones:

- **The CLI process seam** (the e2e suite spawns `python -m crapkit` in throwaway git repositories): worklist rows and header, verify refusal and receipt, unknown scope, artifact refusal, init templates, doctor lane probe, upward discovery from a subdirectory, digest against trend, the partial-run summary, the JSON error object, UTF-8 stdin and BOM files, the one-commit ranking, `rescore --gate --json`. Prior art: the worklist surface, verify basis, lane reuse, init and doctor, encoding and claude-hook e2e tests.
- **The MCP stdio seam** (an e2e client speaking JSON-RPC to `crapkit mcp`, plus a new in-process test driving the serve loop on a string pair): argument validation, ping, the escaped-exception reply, the scope arguments, the `gate` tool, structured content rules. Prior art: the MCP e2e and no-config tests, the registry unit tests.
- **The Action seam**: the comment renderer's unit tests over recorded payloads (verdict phrase, bullets, accepted-debt suffix, the no-base line, the no-verdict line) and the action contract tests that read the workflow definition's steps (exit only in the exit step, two verify calls, every input named in the README). Prior art: the action contract tests.
- **The docs contracts** move deliberately: the exact strings they pin (header suffix, row endings, the marker table, the default-exclude pairs, the "plain text" MCP rows, the `--repo` default) are updated in the same commit as the behavior, and each commit names the contract it moved.

Every function touched stays at ccn 6 or under; the release gate (crapkit on itself) is the last test.

## Out of Scope

- The eleven items the judge rejected or set aside: an lcov parser, SARIF fingerprints, base-run caching in the Action, merging `brief` into `explain`, one js lane per workspace and runner, the hook reporting worsened marked debt, an outputSchema per tool, and the heavier artifacts-record variant of item 7.
- The "hot" and "over-target" row markers under the floor (item 2's deferred part).
- Any new dependency, any hosted component, any second coverage format.

## Further Notes

- Item 10's skeptic surfaced a separate latent bug: `verify --json --github` prints annotations to stdout and breaks the one-object promise. It gets its own ticket.
- Item 7's Action half matters only with `clean: false` on a persistent runner; the CLI half (`coverage` fails, then `verify --reuse-artifacts` passes and becomes the baseline) is the wider exposure and the priority.
- Item 5 and item 9 change what a committed configuration selects or where it is found; both carry an upgrade note.
- Version: 0.5.0 opens the 0.5 line (settled in the grill); 0.5.1 is reserved for the first repair.
